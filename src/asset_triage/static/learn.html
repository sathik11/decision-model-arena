LLMs generate.
Decision models decide.

Most agent work is not writing — it is judging. Route this, gate that, rank these, verify the other. A generative model answers those by writing tokens. A typed decision model returns the judgement itself. This page explains the idea in five minutes so you can take it to a customer, then hands you a live demo that proves it on real infrastructure.

01The idea

Where each model sits.

One turn of an agent loop, left to right. The decision model assesses, your code owns the consequence, and the LLM writes only when writing is actually the job.

INPUT

Context

User message, tool output, sensor state, retrieved documents.

→
DECIDE

Typed model assesses

Several bounded questions answered in parallel against the same state.

→
DETERMINISTIC

Your code routes

Thresholds and policy. Code owns the consequence, not the model.

→
A · GENERATE

LLM writes

Explanation, summary, customer-facing reply.

B · ESCALATE

Human review

Confidence low, or the stakes are high.

Then loop back to context for the next turn. An agent repeats this cycle constantly — which is exactly why the cost of each judgement compounds.

03Where it earns its place

Five jobs an agent repeats constantly.

If you are looking for a first use case with a customer, look here. These are the steps that run thousands of times a day and rarely need a sentence.

Route

Which team, tool or sub-agent should handle this?

Gate

Does this meet policy criteria before we act?

Rerank

Which retrieved result is actually relevant?

Verify

Does this generated output meet the criterion?

Judge

Is this response supported by the evidence?

Thousands of small judgements, every minute. That is where typed answers and code-owned thresholds beat re-prompting an LLM.
04Where Foundry sits

This is not Foundry versus something else.

Foundry is the platform in every pattern below. The decision model is a component Foundry calls — it replaces a prompt, not the platform.

Foundry owns

  • The agent, the orchestration and the tools
  • Evidence, retrieval and grounding
  • Generation wherever language is the deliverable
  • Tracing, evaluation and continuous monitoring
  • Identity, RBAC, network isolation and governance
  • The model deployment and its lifecycle

The typed model owns

  • Bounded judgements with pre-declared options
  • Probabilities your code can threshold on
  • The high-frequency inner loop
  • Nothing customer-facing, and nothing unbounded
It never decides the consequence. Your policy code does.
05Which one, when

Say this. Not that.

The fastest way to lose a technical audience is to overclaim. These are the honest lines, and they are strong enough on their own.

Defensible

  • "The answer is typed, so there is no JSON to parse and no parse failure mode."
  • "Options are declared in advance, so the model cannot invent a route."
  • "You get calibrated probabilities, so your code owns the threshold."
  • "On a GPU this returns in about a tenth of a second."
  • "It is a component inside Foundry, governed like any other."

Do not say

  • "It uses zero tokens." It reads input like any model, and providers may bill it.
  • "It replaces your LLM." It replaces a prompt in the loop, nothing more.
  • "It is always cheaper." On CPU it is slower than the LLM it is meant to beat.
  • "The probabilities are calibrated out of the box." Ordering is stable; absolute values shift with wording. Validate on the customer's own data.
  • "Jev and Laya are the same." Same shapes, different weights and calibration.
06Qualify it

Is this a fit?

Good fit

  • The same judgement runs thousands of times a day
  • The answer is a label, a level or a yes/no — not a sentence
  • Latency in the inner loop is a real constraint
  • The options are known and stable
  • Policy must be auditable and owned by code

Poor fit

  • The deliverable is language: summaries, replies, code
  • The option set changes constantly or is open-ended
  • Volume is low — a prompt is simpler and good enough
  • The task needs multi-step reasoning or tool use
  • No GPU available and latency matters
